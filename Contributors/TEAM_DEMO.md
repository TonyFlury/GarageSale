# Team demonstration data

`seed_team_demo` uses Django's configured database and media storage. It selects
exactly the same current event as the spreadsheets: the latest `use_from` before
today, then event date and primary key to break ties. That event must not have
passed. The command never creates or changes event configuration.

Run from the project root using the configured Python interpreter:

```sh
/home/tony/.virtualenvs/GarageSale/bin/python3.12 manage.py seed_team_demo --dry-run
/home/tony/.virtualenvs/GarageSale/bin/python3.12 manage.py seed_team_demo
```

Optionally add `--user-email existing-team-member@example.com` to attribute new
history and statuses to an existing user. Otherwise the user field is empty.
No emails are sent and no user accounts are created.

All sponsors have original SVG logos generated by the command. They are stored
under `contributors/team_demo/` in the configured media storage. Serve media
normally so they appear in the application. Contacts use fictional names,
reserved example email/domain addresses and fictional UK telephone numbers.

Contact dates are after the last past event, so exactly four of these sponsors
appear under the contacted filter. Two have different notes on the same day,
which is useful for demonstrating date-and-note CSV duplicate checks. Trader
invitations are normal event-status records, so their RSVP links work through
the existing application without sending invitation emails.

Rerunning the command does not duplicate the seed records and preserves edits
made during a demonstration. It does not reset statuses, erase contact history,
or remove donations. The 50/50 and status counts describe a fresh seed; subsequent
manual changes remain in place. Activating a different event and rerunning seeds
the corresponding statuses, notes and donations for that event. Conflicting or
duplicate reserved names cause an error before any records are written.

For PDF and email template demonstrations, configure suitable active templates
in the Sponsor and CraftMarket categories first. This command does not create
communication templates. The invalid example addresses do not receive mail;
use PDF generation or a development mail backend when demonstrating content.
