# Garage Sale Diary training transcript

Voice: natural synthetic British English narration, `en-GB-SoniaNeural`.

## 00:00:00 — Your tasks, in one place

Welcome to the Garage Sale Diary. A diary is the task list for an event. A task records a piece of work. Its due date is when the work should be finished. Its owner is the responsible person or group. Alex is a Diary User who works on assigned tasks. A group shares responsibility among its members. Orange highlights show the controls we use.

## 00:00:28 — Templates and event milestones

A template is a reusable set of tasks for an event. A milestone is a key event date, such as booking opening or the event day. Templates add a known task set to each event, with due dates related directly to its milestones. For example, preparation can be due seven days before bookings open. The details of template creation and management are covered elsewhere.

## 00:00:56 — Dependencies, readiness, and blocking

Some tasks must finish before other tasks. These links are called dependencies. Tasks generated from a template can be linked this way. The earlier task is called a predecessor. A task is blocked while required predecessors remain unfinished. It becomes ready when those predecessors are complete. These links define the work order, separately from the due dates.

## 00:01:25 — Late does not always mean blocked

My Diary shows tasks assigned to you and your current groups. A task can be ready and late, or blocked and late. Late means incomplete and due today or earlier. Ready means its predecessors are finished. Upcoming ready tasks remain available before their due date.

## 00:01:47 — Filter the list

The default list hides blocked tasks. Select show blocked also, then Apply filters, to include them. Whole-team tasks are shared by the entire Diary team. Select include whole-team tasks to bring that shared work into your list. These choices change what you see. They do not change a task or complete any work.

## 00:02:12 — Use a specific status

Use Task status for All open tasks, Late only, Ready and not late, or Blocked and not late. The status links provide quick alternatives. Late takes priority in the counts, so a late blocked task belongs in Late. Clear filters restores the default view.

## 00:02:33 — Add your own task

Choose Add task to create a personal reminder. Ordinary users create tasks for themselves. They cannot assign another owner or add their task to the shared template. Personal additions are private from other ordinary users, but Diary Managers can inspect them. A private task cannot be used as a dependency.

## 00:02:57 — Choose the name and date rule

Enter a clear task name and a short description. Here we create a reminder to call the printing company. Choose One-time date and enter an exact date. A milestone rule uses an event date. An annual rule selects a month and day; it does not create a repeating task. Complete only the fields for the selected rule. There is no dependency editor on this form.

## 00:03:25 — Inspect your saved task

Return to the My Diary page. Find the task named “Call the printing company”, then choose its View and update task button. Its source is Diary addition, which means it was created directly in this diary. It belongs to Alex, has no open predecessors, and is ready. Personal tasks do not change the template or other event diaries. This is a reminder for this diary only.

## 00:03:54 — Change a personal due date

You can change the due date of your own open personal addition. Set the revised date, then choose Save due date. This affects this diary only. Ordinary users cannot change dates on copied template tasks. A completed task cannot have its due date changed.

## 00:04:15 — Keep a useful note

Use Notes to record progress or information for the next action. Enter the note, then select Add note. The diary records its author and time. The history is the saved record of notes and actions. New notes do not replace earlier notes. Assigned users and managers can add notes, including after completion.

## 00:04:41 — Complete finished work

When the work is finished, select Complete. The task records who completed it, when it was completed, and its due date at completion. Completion removes it from the personal open-task list. A note alone does not complete a task. You can still add a follow-up note to the completed record.

## 00:05:04 — Understand an open predecessor

Return to the My Diary page. Find the task named “Open advertising bookings” and choose its View and update task button. It is blocked by the task named “Prepare advertising bookings”. Check Open predecessors before trying to complete a blocked activity. In this example, the predecessor is also late. A task can therefore be blocked even when its own date is in the future.

## 00:05:32 — Blocked work cannot complete normally

If we select Complete while the predecessor remains open, the diary rejects the action. Nothing is completed. Read the message, then resolve the earlier work. Diary Users cannot force the chain to complete. The manager Close all action will be demonstrated later.

## 00:05:54 — Record progress on shared work

Return to the My Diary page. Open the task named “Prepare advertising bookings” using its View and update task button. Alex belongs to its assigned group and can add a note. Record what was checked before completion. The task is late, but it is ready because it has no unfinished predecessors. Its template date is not editable by this ordinary user.

## 00:06:22 — Complete the predecessor

On the task named “Prepare advertising bookings”, choose Complete. This records completion of that task only. The diary recalculates the dependent activity from the saved dependency chain. Completing this preparation does not automatically complete the task named “Open advertising bookings”. It makes that next task available to finish normally.

## 00:06:48 — The next task is now ready

Return to the My Diary page and open the task named “Open advertising bookings”. It is now ready, with no open predecessors. Perform the work before selecting Complete. The due date has not moved. A newly unblocked task can still be late. This is how normal task progression works through the example template.

## 00:07:15 — Review the full event diary

We now switch to Morgan, a Diary Manager. The sidebar includes Manager Diary and Templates. Manager Diary shows the full permitted event diary, including personal additions. Managers can inspect details, record notes, assign new tasks, and change permitted dates. An orphaned task is a template task with no eligible owner. Managers can recover those assignments.

## 00:07:45 — Manager filters

The manager has three filters: include completed tasks, exclude blocked tasks, and exclude non-late tasks. Apply filters combines the selected choices. Here we include history and hide blocked work. Completed tasks remain history and are never marked late or blocked. Clear filters restores the standard open-task list.

## 00:08:11 — Find late tasks

Select exclude non-late tasks and apply the filter to focus on overdue work. A late task is incomplete and due today or earlier. Filters do not resolve the work or remove dependencies. Clear filters before reviewing the full diary again.

## 00:08:30 — Orphaned template tasks appear first

On the Manager Diary page, the task named “Close advertising bookings” appears first because its original owner is no longer eligible. For training, Jamie was assigned this template task and then made inactive. Only template tasks qualify as orphaned. A manager can leave one unresolved, but it remains unfinished and its dependent tasks remain blocked.

## 00:08:57 — Choose a replacement owner

Return to the Manager Diary page. Open the task named “Close advertising bookings” using its View and update task button. Choose a new owner type. Person offers eligible active Diary Users. An ownership group assigns the work to the eligible members of an authorized group. Whole team makes it shared team work. Here we select Alex as the replacement. Recovery applies to open orphaned template tasks. It is not a general reassignment tool.

## 00:09:32 — Recovery preserves the task

The task keeps its identity, due date, and dependency chain. It is no longer orphaned. Reassigning this diary task does not rewrite the source template or other existing diaries. Review template ownership separately when planning future events. Add a note explaining the handover.

## 00:09:54 — Change a template task due date

Managers can change the due date of an open copied template task. On the task named “Close advertising bookings”, we move its due date. Save due date changes this diary only. The original milestone rule remains visible. A date override replaces the calculated date for this task. The diary does not warn if that causes a scheduling conflict. Check dependencies and dates yourself.

## 00:10:25 — Create a manager-assigned task

Return to the Manager Diary page, then choose Add task. Managers can assign a person, an authorized ownership group, or Whole team. We create a shared equipment check for the Executive Member group. The task remains a diary addition unless the separate template option is explicitly selected.

## 00:10:48 — Keep diary work separate from templates

The lower section offers Add to template for future diaries. That is a separate decision and requires a reusable date rule. We leave it off and save this task only. Existing diary dependencies remain fixed, and the new task is not inserted into an existing dependency chain.

## 00:11:10 — Inspect the blocking chain first

Return to the Manager Diary page. Open the task named “Complete final event checks” using its View and update task button. It is blocked by advertising and sale-booking work. The Open predecessors section lists the unfinished chain. A manager should inspect it before using Close all. Normal Complete still requires predecessors to finish. Close all is the privileged alternative.

## 00:11:40 — Close all completes the open chain

Close all completes the selected task and its open predecessor chain together. It does not merely hide a warning or remove dependencies. Use it only when that completion is intended. We choose it now for this demonstration. The diary records Morgan as the acting manager.

## 00:12:01 — Review the completion history

Return to the Manager Diary page and select include completed tasks. Then choose Apply filters. The completed records show who acted and when. The predecessor records also explain forced completion, which means completion through the manager Close all action. The task named “Run the Garage Sale” remains separate: completing its predecessor makes it ready, not completed.

## 00:12:30 — Audit a forced predecessor

Return to the Manager Diary page and include completed tasks. Open the task named “Close advertising bookings”. Its history records forced completion for the task named “Complete final event checks”. The earlier note is retained. Completion history and notes provide context for the next manager. Read the record before taking another action, and reload a task if the diary reports that its saved state has changed.

## 00:13:01 — A practical daily routine

For everyday work, check Late, inspect blockers, add useful notes, and complete work in order. Use personal tasks for your own reminders. Managers review orphaned tasks, apply filters, and use date or ownership recovery carefully. Close all is an explicit completion of the chain. This concludes the Garage Sale Diary walkthrough.
